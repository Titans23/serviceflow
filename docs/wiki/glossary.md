# 术语与边界

这里列的是 ServiceFlow 实际使用的含义，便于从简历或设计说明回到代码。

| 术语 | 在本项目中指什么 |
| --- | --- |
| 工作流 / Workflow | LangGraph4j 组织的有状态路由与节点执行，不是任意工具自主循环 |
| 查询计划 | 一次模型输出的受约束 JSON，后端校验后执行既有查询工具 |
| Checkpoint | Redis 中的图状态快照，不是订单或退款的执行凭证 |
| 幂等 | 同一业务请求重复到达时保持首次结果，不重复创建操作或退款 |
| 订单版本 | 确认卡生成时绑定的版本；实际执行时检查订单是否已经变化 |
| Outbox | 与业务记录同事务写入的待投递记录，用于驱动后续通知 |
| Publisher Confirm | RabbitMQ 对发布的确认，不代表业务任务完成 |
| 租约 / leaseToken | 限期处理权及其身份标记，阻止过期工作线程覆盖新执行结果 |
| 查询优先 | 渠道结果不明时先查原退款编号，不能直接重新发起退款 |
| 活动版本 | MySQL 指定的当前可检索文档版本，只有完整 READY 的版本才能激活 |
| RRF | 根据两路排名做倒数排名融合，此处 k=60 |
| Reranker | 用问题与候选段落重新计算相关性，选前五 |
| Grader | 判断证据是否足以回答原问题，并筛选证据；与离线答案判分不是同一个角色 |
| Grounded answer | 模型选事实编号，后端校验后输出目录事实或完整来源段落 |
| Recall@5 / MRR@5 | 检索阶段的章节覆盖和首个相关结果排名指标 |
| 规则通过率 | 是否符合冻结的事实与范围标签，不等于独立人工语义正确率 |
| Demo | 不调用真实模型的业务演示模式；用于验证流程，不能证明模型质量 |
