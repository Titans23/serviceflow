# RAG 数据集与真实评测

检索指标回答“相关证据有没有被找出来”，答案规则回答“最终选择是否符合标签”，业务验收回答“操作是否正确执行”。这三类结果分别报告。

## 题目与证据标签如何构建

语料来自已入库的公开商品资料。[v2 数据集](../../quality/evaluation/datasets/rag-retrieval-v2.json) 保留每份来源的哈希、v1 父版本和修订前问题，以资料章节、事实编号和完整参考段落建立可追溯标签。

- **104 条修订回归题**：已用于诊断；其中 13 条澄清问法，20 条补充明确允许的事实范围。
- **40 条冻结新题**：19 条单证据、11 条多证据、10 条无答案题。首次运行前提交冻结，本轮不根据输出调参或修改标签。
- **必需 / 可选 / 禁止事实**：可选补充不能弥补必需事实遗漏；禁止事实用于识别错误范围。无答案题单独检查拒答。

新题使用已知来源，没有与回归集共享问题，但不是新来源留出或独立人工标注基准。商品与版本过滤后每题通常只有约 8 个章节，不能把这里的满召回外推到大知识库。

## 一次评测如何执行

1. 固定代码、数据哈希、模型、参数、资料与活动版本。
2. 管理员通过显式开启的 [RagEvaluationController](../../apps/serviceflow-server/src/main/java/com/serviceflow/controller/RagEvaluationController.java) 执行固定商品问答。只提供名称/SKU，避免目录参数直接代答。
3. [rag_benchmark.py](../../scripts/evaluation/rag_benchmark.py) 按固定随机种子和轮换配置顺序发请求，预热独立标记，正式每题每配置只测一次、并发为 1。
4. 用诊断编号关联各阶段 trace 和完整分块，验证商品与版本，再由 [rag_metrics.py](../../scripts/evaluation/rag_metrics.py) 离线计算指标。
5. 供应商请求受全局预算控制，发生供应商错误停止，不自动补跑；失败与未执行项保留在计划分母中。

v1 比较五种配置，包括有界改写。v2 使用修订标签，比较中文 BM25、向量、混合、混合加重排四组，**不启用改写**。不能称为 v2 五组对照。

## 指标的分母

| 指标 | 含义与范围 |
| --- | --- |
| Recall@5 | 可回答题所需章节在前五候选中的覆盖比例，再做逐题宏平均 |
| MRR@5 | 前五中第一个相关章节排名的倒数；没有命中计 0 |
| 答案规则通过率 | 必需事实、允许范围、禁止事实和不足标记是否满足冻结规则 |
| 上下文覆盖 | Grader 后保留下来的证据能否覆盖所需事实 |
| P95 | 单并发完整 HTTP 耗时，含检索、模型与诊断写入，排除预热 |
| 请求量 | 实际供应商请求数，包含入库、预热、正式问答；不是估算 token 或账单 |

本轮没有独立 LLM-as-Judge 或人工语义正确率。固定商品评测也不覆盖完整 Agent 意图路由、用户上下文与工具执行。

## 最新真实结果

2026-11-16 完成 144 题 × 4 配置，576 次正式问答、4 次预热，调用错误为 0；含入库共 1932 次供应商请求。完整统计与失败案例以 [v2 报告](../../quality/evaluation/results/rag-retrieval-v2-2026-11-16.md) 和 [JSON](../../quality/evaluation/results/rag-retrieval-v2-2026-11-16.json) 为准。

40 条冻结新题的摘要如下，Recall/MRR 分母为其中 30 道可回答题，规则通过率分母为 40：

| 配置 | Recall@5 | MRR@5 | 规则通过 | P95 |
| --- | ---: | ---: | ---: | ---: |
| 中文 BM25 | 100% | 0.9611 | 39/40 | 2.930 s |
| 向量 | 100% | 0.9833 | 39/40 | 3.238 s |
| 中文混合 | 100% | 0.9667 | 39/40 | 3.401 s |
| 中文混合 + 重排 | 100% | 0.9833 | 39/40 | 3.330 s |

四组共同的失败是额外选入了本题标签禁止的有线快充段落，而用户询问无线充电配套。必需事实已找到，问题出在回答范围；这说明满召回不代表每个回答都合格。

## 什么收益能归因

使用完全相同的 v2 问题和文档，直接比较 standard/chinese 两个集合：126 道可回答题的 BM25 Recall@5 从 **56.75% 到 100%**，MRR@5 从 **0.3657 到 0.9828**。这个本地配对不经过答案模型，没有额外云调用，能够分离分词配置的影响。

本轮未证明混合或重排增加了新题回答通过数，四组均为 39/40。v1 与 v2 的问题、标签不同，不能直接相减来宣称回答质量提升；v1 原始记录仍按旧规则重算一致。默认业务检索链路也没有因为单轮结果被自动切换。

## 继续验证什么

优先补来源不同、候选更多、容易混淆的证据，并对范围超出和不足标记做人工复核。新的付费评测需要单独确认范围与预算，不能为了增加简历数字反复重跑并挑选成绩。
