**AI 审核，无独立人工复核。** Codex 整理并审核 220 项事实及标签组合，脚本逐条检查 900 条的支持覆盖、引用、充分性逻辑和格式。机器检查不能替代独立语义复核。

训练前二次语义审核发现三组公共范围文字泄露其他事项的答案（录音转文本、待办位置提醒、天气城市上限），已移除这些公共提示中的答案信息，只在对应事实块保留。注入措辞也改为与纯/混合类别独立随机选取。旧数据和准备目录完整保留在 `grader-specialist-exp-01-pretraining-r0`，没有在该版上启动冒烟、正式训练或预测；新版本重新审核、冻结。通过门槛未改。这次修订不依据任何模型输出。

来源版权归原权利人，官方页面没有被视作开放许可证训练数据。保留原始快照与抓取时间，训练文本使用事实转述和项目编写的问答夹具；不向项目商品知识库写入模拟事实，不公开再分发原文快照。

### 测试范围的限制

这是由官方事实构造的 FAQ 式证据夹具，不是生产检索流量。适用范围冲突通过显式模拟发布通道构造，不声称真实华为产品具有这些通道限制。验证偏向未见 PC 支持功能，测试是其他未见功能，存在领域差异。

“未见来源”指来源组未用于本次 SFT 训练；无法排除原始基座在预训练时接触过公开页面。

适用范围冲突类共有模拟发布前缀，可能形成模板捷径。因此该类的高分不能单独证明真实型号/版本冲突的泛化。需要同时查看旧压力集的不同表达与实际模型范围冲突表现；不能仅凭新集总分解释改善来源。本限制在新验证/测试生成前记录，不改变预登记门槛。

来源和事实谱系互斥，但六种任务结构跨集合共用；未测量任意长文、复杂冗余证据、多种等价支持集或所有注入攻击。此次唯一支持集合按无序集合评分，不要求等价排列。结果仅能支持该范围内的结论。

## 固定训练与恢复

原始 Qwen3-8B revision `b968826d9c46dd6066d109eabc6255188de91218`，本地来自 ModelScope 固定 revision；LLaMA-Factory commit `ca75f1edf3cb50343ed1c98605141c3e22075b5f`。Python 3.12.14、PyTorch 2.6.0+cu124、Transformers 4.52.4、PEFT 0.15.2、vLLM 0.8.5。

LoRA r16/alpha32/全部线性层，BF16，LR 1e-4，micro batch 1，梯度累积 16，4096 上限，仅 assistant loss，梯度检查点，余弦学习率、5% warmup。独立 8 步冒烟；两个正式种子各最多 2 epoch，均从原始基座重新初始化。

每 epoch 先封存完整 checkpoint，再复制轻量 adapter，最后轮换删除已验证的旧完整 checkpoint。轻量 adapter 不含优化器、调度器和 RNG，不能用于完整续训。异常中断只能回到最近完整 epoch。无完整 epoch 时不能声称已支持该次恢复。

## 评分和选择

仅验证集选 epoch：综合正确率最高，然后误判充分次数最少，然后较早 epoch。两个种子独立选择，选择记录绑定验证预测散列，封存后才运行新测试。

主指标同时要求：严格 JSON 与合法引用、充分性正确、支持 ID 集合正确。重复 JSON 字段、重复或候选外 ID、无响应和超时均不能算对，失败不从分母删除。

两个种子都必须综合准确率至少 80%、相对基座至少 +15 个百分点，多段与部分题各至少 80%，不充分被判充分至多 10%，格式引用合法率 100%，纯注入失败为零。种子 42 为预登记主实验，15 个来源组配对重采样 10,000 次，95% 区间下界须大于零。门槛保持原样。

旧压力和旧 100 条模块集只作回归，其他任务的关键词指标不能冒充独立事实正确率。只有通过质量门槛才进入真实 Java `evaluateEvidence` 的隔离验收；失败则停止追加 epoch，报告原因。

## 当前验证

训练工具本地单元检查 72 项通过，包含新增集合评分、非法 JSON、部分证据、失败分母、epoch 选择与 adapter 完整性检查，以及既有 checkpoint 检查。新测试另有来源/问题注册表，改成 train 标记也不能绕过隔离。这不是正式模型实验或 Java 验收结果。

9 月 16 日的定向检查中，新增 Java 故障边界检查 6 项通过：部分支持保留、伪造 ID 过滤、空选择不能充分、坏 JSON 异常、实际 20 秒超时预算、Grader 异常后保留证据且标记不足/降级。没有数据库或外部模型调用。5 项真实模型验收当时已编译，但在质量门槛判定前保持跳过；这些跳过项不算验收通过。定向 Maven 检查跳过仓库既有全量格式问题，不声称全量 `mvn verify` 通过。

9 月 17 日完成质量门槛后，5 项真实模型 Java 用例实际执行并全部通过。首次尝试在 Maven 缓存权限处失败、未执行模型用例；保留失败记录，离线依赖检查通过后在新目录重试，并新增 2 项“拒绝旧测试报告”的工具检查，均通过。模型、Java 用例、提示词和门槛没有改变。最终验收以实测报告链接的本次新生成凭据为准。
